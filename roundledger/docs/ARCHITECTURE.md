# Architecture and security

```
Chrome (customer)                                   Server (Node 22, one process)                 Google
┌──────────────────────────────┐   HTTPS + Bearer   ┌──────────────────────────────────────┐  HTTPS   ┌────────┐
│ side panel (UI)              │ ─────────────────▶ │ /api/auth, /api/me, /api/license     │ ───────▶ │ Gemini │
│ service worker               │                    │ /api/devices, /api/rounds, /api/stats│ x-goog-  └────────┘
│   adapters + round tracker   │                    │ /api/ai/analyze (server-side key)    │ api-key
│ content scripts (opt-in)     │                    │ /api/admin/* (cookie, admin role)    │
│   page-hook (read-only WS)   │                    │ /admin/ (static dashboard)           │
└──────────────────────────────┘                    │ SQLite (WAL) + AES-GCM secret store  │
                                                    └──────────────────────────────────────┘
```

## Components

| Path | Purpose |
|---|---|
| `shared/` | Analysis, round tracker and platform adapters. Used by both the extension and the server tests. |
| `server/src/` | HTTP server (no framework), routes, services, Gemini provider, migrations runner. |
| `server/migrations/` | SQL schema. |
| `admin/` | Dashboard (vanilla ES modules, no build). |
| `extension/` | MV3 extension source. `npm run build:extension` assembles `dist/extension`. |
| `installer/windows/` | NSIS script, notice, setup guide, assets. |
| `branding/` | Logo source and brand tokens. |

## Licensing model (server-authoritative)

- Entitlement is computed by the server on every request from `subscriptions` (paid beats trial; suspended/revoked/expired never count).
- Trials: one per account **and** one per installation (`trial_claims` UNIQUE keys) inside an IMMEDIATE transaction. Local extension data cannot extend or restart a trial.
- Activation codes: random 16-char Crockford base32 with an `RL-` prefix (80 bits), stored as SHA-256 hashes. Redemption is compare-and-set in a write transaction, so a code can be redeemed only once even under concurrent requests.
- Device limits are enforced at extension sign-in. Each extension session is bound to a device row; revoking the device kills its sessions.
- What the extension enforces locally: recording rounds and showing local statistics require a cached active entitlement. A modified extension could bypass that local gate. Cloud history, AI explanations and everything administrative are enforced server-side and cannot be bypassed.

## Security controls

| Area | Control |
|---|---|
| Passwords | scrypt (N=16384, r=8, p=1, 16-byte salt); min 10 chars with letters and digits; constant-time compare; dummy hash for unknown emails |
| Brute force | per-IP rate limits on auth/register/redeem; account lock after 10 failures for 15 minutes |
| Sessions | 256-bit random tokens, stored as SHA-256; extension: Bearer token in `chrome.storage.local`, 30-day sliding; dashboard: HttpOnly + SameSite=Strict (+Secure on https) cookie, 12 h |
| CSRF | cookie-authenticated writes require `X-Requested-With: RoundLedger`; CORS only for allow-listed extension origins |
| Authorization | route-level `user`/`admin` checks on the server; admin cannot suspend self; web login refuses non-admins |
| Input validation | typed validators on every body/query field; 64 KB body cap; JSON-only; LIKE wildcards escaped; parameterized SQL everywhere |
| Secrets | Gemini key encrypted with AES-256-GCM under `APP_ENCRYPTION_KEY`; write-only API; masked hint; sent only in the `x-goog-api-key` header; redaction of key-like strings in logs, audit details and client error reports |
| Headers | CSP `default-src 'self'` (no inline script), `X-Frame-Options: DENY`, `nosniff`, `Referrer-Policy: no-referrer`, HSTS on https |
| Paid API calls | generation tests need explicit confirmation; per-user and global daily caps; one in-flight analysis per user |
| Extension | no broad permissions at install; game-site access is requested at runtime per origin; page hook only listens; content scripts can only send `ws` frames, the panel API rejects them; build fails if a provider key, a direct provider URL or betting-automation terms appear in the package |
| Audit | append-only audit table for admin and security-relevant actions, with scrubbed details |
| Dependencies | zero npm runtime dependencies (nothing to audit beyond Node itself) |

## Known limitations

- Single-process server (SQLite + in-memory rate limiter). Scale vertically, or move to Postgres and a shared limiter if needed.
- No email delivery: no email verification or self-service password reset. Admins can reset a password from the user page (the user is signed out everywhere); add an email provider if you want self-service resets.
- No payment processor. Codes are generated by admins and sold elsewhere.
